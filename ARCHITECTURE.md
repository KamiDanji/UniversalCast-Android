# Architecture

```
 Sender ──mDNS──▶ _universalcast._tcp ─┐
 Sender ──WSS (pinned TLS)──▶ UcpServer ─▶ UcpProtocolHandler ─▶ PlaybackEngine ─▶ Media3PlaybackEngine ─▶ ExoPlayer / Photo / Audio UI
        ▲                        │            │  ├ Authenticator (challenge/response)     └─ TextRenderer Offset Proxy
        │                        │            │  ├ PairingManager (QR, SAS, approval)     └─ PlaybackQueue (Up Next / Auto-play)
   MediaProxyServer (HTTP)       │            │  ├ SessionManager (1 active / 30m detached grace)
   (local files + locked HLS)    │            │  └ SenderRegistry ─▶ EncryptedFileSenderRegistry (AES-GCM, Keystore key)
                                 └ ReceiverIdentity ─▶ KeystoreIdentityProvider (EC P-256, AndroidKeyStore)
```

## UI design system (since 1.1.0)
- **Phone (`:sender-app`)** is full Material 3: `Scaffold`/`LargeTopAppBar`, M3 `Card`s, `TabRow`, `FilterChip`s, `ModalBottomSheet`,
  `SegmentedButton`s, extended icons. `SenderTheme` uses **dynamic (wallpaper) colour** on Android 12+ and otherwise one of
  six seeded palettes (Ocean, Violet, Lagoon, Forest, Rose, Sunset) generated by `schemeFromSeed` (M3 tone assignments over
  CIE L*C*h, unit-tested for WCAG AA contrast), in light, dark or system mode. Choice is stored in `ThemePrefs`
  (SharedPreferences) and edited in the *Appearance* sheet on Home. Edge-to-edge; themed (monochrome) launcher icon.
  Success/caution colours come from `MaterialTheme.status` (not an M3 role).
- **TV (`:app`)** uses **TV Material** (`androidx.tv.material3`): `Button`/`OutlinedButton`, `Surface`, `ListItem` + `Switch`,
  with the library's own D-pad focus treatment. TV Material has no dialog, progress or text field, so `Components.kt` provides
  `TvDialog`, `TvProgressBar`, `TvSpinner` and `TvTextField`. One fixed dark seeded scheme (no dynamic colour on TV).
- **Splash**: phone = `core-splashscreen` system splash handing over to an animated in-app splash drawn in the live
  colour scheme (tap to skip); TV = animated in-app splash in TV Material colours (any key skips).

## Modules
- **:core** – no Android. `ucp` (JSON, envelopes, protocol constants), `security` (crypto, TLS pinning, identities),
  `pairing`, `auth`, `session` (`SessionManager` with detached grace period), `identity` (roles/permissions/registry),
  `network` (server + handler), `discovery`, `config`, `storage`, `playback` (`PlaybackSnapshot`, `PlaybackQueue`,
  `SubtitleStyle`, `VideoScaleMode`, `RemoteKey`), `sender` (controller + Dummy TV simulator, `MediaProxyServer`,
  `CastHistoryStore`/`BookmarkStore`, browser-cast logic, `AdBlocker`, `FilterEngine`), `cli.UniversalCastCli`, and
  `core.ReceiverCore` (composition root).
- **:app** – `ReceiverRuntime` (process-wide state as StateFlows + OSD/subtitle style wiring), `service.ReceiverService`
  (foreground service, multicast + wake lock, network callback, `OverlayAnchor`), `platform` (Keystore, NSD,
  `Media3PlaybackEngine`, `TvRemoteDispatcher`, `TvRemoteAccessibilityService`), `policy` (`AutoLaunchPolicy`,
  `CastStartDetector`, `PlayerOsdTracker`), `ui` (Compose screens: Home, Pairing, Devices, Player, AmbientScreen,
  Settings, UpdatePrompt).
- **:sender-app** – `SenderRuntime` (Keystore identity, encrypted TV list, `SenderController`, NSD discovery,
  `MediaProxyServer`, `CastHistoryStore`, `BookmarkStore`, `FilterLists`), `ConnectionService` (background keep-alive
  service + Android `MediaSession` & `VolumeProvider`), `ContentUriMediaSource` (random-access `content://` reader),
  and Compose screens (Home, Pair, Remote [Media & Cast + TV Remote & Touchpad/D-Pad/Keyboard], Browser, About,
  UpdatePrompt).
- **:updater** – `Release.kt` (`Versions`, `ReleaseParser`, `TrustedHosts`), `Markdown.kt` (`MarkdownParser` for release
  notes), and `UpdateManager.kt` (GitHub Releases HTTPS check, SHA-256 verification, `PackageInstaller` commit).

## Phone app (:sender-app)
`SenderRuntime` + Compose screens (Home, Pair, Remote, Browser, About). Core logic lives in `:core` so it can be
tested end-to-end against the real receiver:
- `sender.PairingSession` – pairing ceremony (address fallback, SAS, verified approval).
- `sender.SenderController` – single worker thread (keeps request sequence numbers ordered), pinned connect,
  lazy session creation, commands (playback, track selection, subtitle offset/style, video scale, sleep timer, queue,
  remote keys/text), event-driven state, heartbeat, reconnect with backoff, failure classification
  (unreachable / rejected / pin mismatch), plus `startDummyMode()` in-process TV simulator.
- `sender.MediaProxyServer` – capability-token-authenticated HTTP proxy (144-bit random token) serving local phone media
  (`/local/<token>/<name>` with `Range` / `206 Partial Content` seeking) and proxying locked web streams
  (`/remote/<token>/stream` & `/ref?u=...` with WebView headers/cookies and on-the-fly `.m3u8` manifest rewriting).
- `sender.CastHistoryStore` / `sender.BookmarkStore` – JSON persistence of recent casts with playback position (for
  1-tap resume, never persisting headers/cookies or ephemeral proxy URIs) and browser bookmarks.
- `sender.EncryptedFileReceiverStore` – AES-GCM persistence of paired TVs.
- `sender.MediaSniffer` / `sender.CandidateList` – pure URL classification (HLS / DASH / progressive / audio /
  subtitle / ignore: segments, keys, images…), subtitle language guessing, and the thread-safe, deduplicated, ranked
  (HLS master > HLS > DASH > progressive > audio, newest first) candidate list of a page that hides variant playlists
  of a known master.
- `sender.StreamProbe` / `sender.HlsParser` – `HttpURLConnection` probe (≤ 256 KiB, 5 s, manual redirects with
  host-scoped Cookie) that classifies by content: HLS master/media/live/duration/subtitle renditions, DASH, HTML page,
  progressive; detects DRM.
- `sender.CastHeaders`, `sender.BrowserCast`, `sender.PageScan`, `sender.MediaCast` – the headers a page's player would
  send, the `media.load` / `queue.add` built from a candidate, the DOM "Scan page" script and its parser.
  `SenderController.load(MediaCast)` / `enqueue(...)` validates headers/subtitles with the receiver's own rules before sending.
- `sender.AdBlocker` + `sender.FilterEngine` (`web/FilterLists.kt`) – compact built-in ad/tracker domain blocklist paired
  with EasyList, uBlock Origin (filters/badware/unbreak), and Peter Lowe's list downloaded over HTTPS every 3 days,
  indexed by host/token, plus cosmetic CSS injection (`cosmeticCss`) while never blocking castable media URLs.

Cast browser (`sender-app/.../web/BrowserScreen.kt`): a hardened WebView. `shouldInterceptRequest` (plus a
service-worker client) sees every request of every frame, filters ads, and feeds `CandidateList`; "Scan page" adds what
the DOM shows. The candidates sheet probes lazily, shows quality/duration/live/DRM, lets the user pick subtitles,
optionally toggle **"Proxy stream through this phone"**, and cast or add to queue (`+ Queue`). After casting, the page's
media is paused and the remote is drawn as an overlay above the still-composed browser.

Background controls (`ConnectionService`): runs a `connectedDevice` foreground service with WakeLock/WifiLock and an
active Android `MediaSession` + `VolumeProvider` so lock-screen media controls, notification seek bar, and hardware
volume buttons control the TV even when the screen is off.

## Receiver side (:app)
`Media3PlaybackEngine`: one ExoPlayer with `DefaultMediaSourceFactory(DefaultDataSource(ResolvingDataSource(OkHttpDataSource)))`
and a custom `DefaultRenderersFactory` that wraps Media3 `TextRenderer` instances in a dynamic proxy shifting
`render(positionUs, elapsedRealtimeUs)` by `-subtitleOffsetMs * 1000L` for real-time subtitle delay/advance.
The resolver adds the current item's headers per request (Cookie only to the media host); an OkHttp network interceptor
strips Cookie on every other hop, including redirects. Subtitles are `MediaItem.SubtitleConfiguration`s loaded through
the same stack; English is the preferred text language, and all audio/subtitle groups are exposed in
`PlaybackSnapshot.audioTracks` / `subtitleTracks` for live mid-playback switching (`selectTracks`).

Additional engine capabilities:
- `PlaybackQueue`: tracks up to 50 queued items (preserving headers in memory only) and auto-advances on `STATE_ENDED`.
- Photo & Audio modes: `image/*` items are fetched via OkHttp and rendered full-screen (`currentPhoto`) with an 8-second
  slideshow timer when queued; audio-only streams (`mediaKind == "AUDIO"`) render an animated equalizer card on `PlayerScreen`.
- `VideoScaleMode` (`FIT`, `ZOOM`, `FILL`) controls `PlayerView.resizeMode` and photo `ContentScale`.
- `SleepTimer` stops playback automatically when the requested countdown expires.
- `TvRemoteDispatcher` (`platform/TvRemoteControl.kt`) executes `remote.key` (D-pad, OK, Back, Home, Play/Pause, Rewind,
  Fast-Forward, Volume/Mute via `AudioManager` or in-app `KeyEvent`s) and `remote.text` (TV clipboard + virtual keyboard
  events via `KeyCharacterMap`). Optional `TvRemoteAccessibilityService` allows D-pad/Back/Home across other TV apps.

## TV app lifecycle
- `ReceiverService` is a `connectedDevice` foreground service (allowed from BOOT_COMPLETED on Android 15, unlike
  `mediaPlayback`). Start failures are logged, never thrown.
- `BootReceiver` (BOOT_COMPLETED, QUICKBOOT_POWERON, MY_PACKAGE_REPLACED) → `shouldAutostart()` → service.
- Auto-open: `ReceiverRuntime` detects a cast start (`CastStartDetector`), the service asks `AutoLaunchPolicy`
  (setting, activity resumed, 2 s debounce, overlay permission on API 29+) and starts `MainActivity`
  (`EXTRA_FROM_CAST`). `OverlayAnchor` keeps a 1×1 overlay window while the permission is granted (Android 15 needs a
  visible one). When a cast-opened playback ends, the activity moves its task to the back.
- **Detached playback**: when a Controller connection closes, `UcpProtocolHandler` calls
  `sessions.detachOrEndForConnection(id, timeouts.sessionGraceMs)` (default `Ucp.SESSION_GRACE_MS` = 30 minutes). Playback
  continues undisturbed until the controller reconnects (`session.create` resumes seamlessly), another controller replaces
  it, the sender is revoked, or the grace timer sweeps out.
- `PlayerScreen`: video/photo/audio visualizer + styled subtitles (`SubtitleStyle`), spinner while loading/buffering,
  optional 2-second floating OSD status pill (`PlayerOsdTracker`), error message; nothing focusable. Back stops playback;
  media keys toggle play/pause (`ALLOW_REMOTE_MEDIA_KEYS`); D-pad does nothing; immersive mode.
- `AmbientScreen`: burn-in-shifted clock, date, and connection status idle screen (manual button on Home or auto-enters
  after 3 minutes of inactivity when enabled in Settings).

## Request pipeline (UcpProtocolHandler)
size → strict decode → duplicate-id cache → sequence → connection phase → permission → payload validation → execute.
Responses allocate their sequence number after routing so events emitted during a request order correctly.

## Threading
Server threads handle protocol (`UcpServer` also runs a 100 ms write watchdog that works around a lost-wakeup race in
Java-WebSocket 1.6.0's NIO write path); ExoPlayer is touched only on the main thread through a synchronous `onMain` bridge;
engine events are re-dispatched on a dedicated executor to avoid main/network lock inversion.

## Extension points
`PlaybackEngine` (new playback backends), `Capabilities.features`/`playbackMethods` (currently advertises
`"session"`, `"snapshot"`, `"events"`, `"seek"`, `"speed"`, `"volume"`, `"media-headers"`, `"subtitles"`, `"tracks"`,
`"subtitle-style"`, `"queue"`, `"remote-input"`, `"detached-playback"`; `playbackMethods` is `"direct-url"`),
`Method`/`Permissions.requiredFor` (including `playback.selectTracks`, `playback.setSubtitleOffset`,
`playback.setSubtitleStyle`, `playback.setVideoScale`, `playback.setSleepTimer`, `queue.*`, `remote.key`, `remote.text`),
and `ServiceAdvertiser`.
